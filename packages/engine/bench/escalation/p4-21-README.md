# P4-21 escalation benchmark corpus

Purpose: record actual results and the specific remaining capability gap for each entry in [`p4-21-corpus-index.md`](p4-21-corpus-index.md), as required by [`PLAN.md`](../../../../PLAN.md) P4-21 and [`README.md`](../../../../README.md) §13.1.3 / §26.

## Evidence rules

- Never fabricate fixtures, reference outputs, measurements, or accuracy/latency numbers.
- Every input asset must have a verifiable licence or be generated in-repo with provenance, exact generation steps, and hashes.
- A benchmark is `MEASURED` only for the tested method and stated input class. Small synthetic samples do not establish broad real-world quality.
- Model-dependent comparisons stay open until the exact model asset is registered and verified, the production runtime executes it, and both local/model outputs are measured on the same fixture.
- Keep deterministic local capabilities that have no material model gap; do not create a model row merely to populate a table.

## Corpus provenance and obtaining more CC0 samples

The four currently registered images are individually listed in [`fixtures/cc0/manifest.json`](fixtures/cc0/manifest.json). The verifier checks the exact image hashes and the source item metadata that declares CC0. [`fixtures/cc0/README.md`](fixtures/cc0/README.md) describes two repeatable acquisition paths: query the Cleveland Museum of Art open-access API and require `share_license_status: CC0`, or query Wikimedia Commons for an individual file and require both `LicenseShortName=CC0` and its CC0 `LicenseUrl`. Capture the API/file metadata snapshot and source URL, download the exact rendition, record dimensions and SHA-256, then run `node scripts/verify-p4-21-cc0-fixtures.mjs`.

## P4-22 reconciliation rule

Update README §13.1.3 only when a measured, relevant fixture demonstrates that Tier 0–2 succeeds or fails for the stated input class. Keep model-specific statements qualified until the corresponding checkpoint has passed register/hash verification and browser inference. Record each accepted or removed escalation in `PLAN.md` §16 in the same change.
