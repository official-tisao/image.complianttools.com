# P4-20 STCC evidence matrix

**Evidence date:** 2026-09-22
**Scope:** T27, T32, T57, T60, T61, T62, T63, T70, T79, T80, and T81.

This matrix is a traceability index for the twelve-item STCC in
[`PLAN.md`](../PLAN.md#04-definitions-used-throughout). A check means that the
linked route, engine, benchmark, or gate contains the evidence. `Qualified` is
used only where the product has a local path and the optional external model or
browser-specific offline limitation is stated explicitly.

| STCC item                        | Evidence used for every target route                                                                                                                                                                                                                                                                      |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Engine operation              | `packages/engine/src/` implementations and the engine test suite; T32/T57 adapters are lazy and DOM-free.                                                                                                                                                                                                 |
| 2. Schema and generated controls | The route option schemas and generated-control assertions in the target E2E files.                                                                                                                                                                                                                        |
| 3. No-op defaults                | Default-control assertions in T27, T32, T60, T61, T70, T80, and T81; T57/T62/T63/T79 use an empty-input/no-output default.                                                                                                                                                                                |
| 4. Happy path and errors         | Target route E2E files listed below plus the matching `packages/engine/test/` suites.                                                                                                                                                                                                                     |
| 5. Adversarial typed remedy      | Unsupported, malformed, oversized, decode, worker, canvas, cancellation, and model-integrity cases are asserted with `data-error-kind` and user remedies.                                                                                                                                                 |
| 6. Prerendered page              | Each target route has a static HTML assertion, including JavaScript-disabled checks where the route has an input surface.                                                                                                                                                                                 |
| 7. SEO                           | Each route asserts canonical URL, alternate links, description, JSON-LD, sitemap/discovery content, and localized page direction.                                                                                                                                                                         |
| 8. Preview/export fidelity       | Each route compares preview pixels or bytes with the download; T57/T62 document the manual/review and text-output semantics.                                                                                                                                                                              |
| 9. Latency budget                | Route measurements are persisted in `packages/engine/bench/escalation/` and the route-budget assertions; broad-device performance is not inferred.                                                                                                                                                        |
| 10. Axe and keyboard             | Axe assertions and keyboard-only controls are present in each route suite; clipboard-only checks remain Chromium-specific where the browser API is unavailable.                                                                                                                                           |
| 11. i18n                         | `en`, `en-XA`, and `ar` route assertions cover labels, direction, discovery text, and control names.                                                                                                                                                                                                      |
| 12. Offline                      | Local paths are exercised after same-page or fresh-page warm-up. T32 Tier 2, CDN-delivered T62 models, and T57 YuNet remain cache-dependent by design; Tier 1/manual paths continue to work offline and the limitation is displayed/documented. WebKit skips the known local File/Blob fresh-reload case. |

## Current limitations

- The matrix closes route-level STCC traceability. It does not turn synthetic
  fixtures into real-photo accuracy evidence or make a Tier 2 host durable.
- T32 model-dependent tests require the registered external model bytes. The
  2026-09-22 local rerun passed all local-path checks but could not fetch the
  four model-dependent fixtures because the configured network timed out; the
  previous successful browser CORS/hash/inference evidence remains recorded.
- T62's 163-file catalogue is registered, but accuracy is measured on eight
  generated language fixtures and one registered English CC0 crop. Hausa is
  absent upstream and is not fetched.
- T57's selected corpus is deterministic, in-repository, and CC0. It measures
  functional and edge-case behavior only; it does not establish real-photo
  face accuracy, plate detection, demographic coverage, or safe redaction.
